## 4. 誘導・評価語の指摘

### 特定の直し方への誘導

明示的に一つの修正方法を命令してはいませんが、次の表現は判断を誘導し得ます。

- `ERROR`、`UNREACHABLE_REFERENCE`、`missing_target`  
  実測なしでも「直すべき故障」と受け取りやすい。
- 「Plugin `vercel` exists but is disabled」  
  plugin有効化を自然な解決策として連想させる。ただし、参照削除・名称修正・意図的無効化の可能性もある。
- drift findingsの「The ... copy is newer」  
  新しい側を正本としてコピーする判断を誘発するが、mtimeは正しさの根拠にならない。
- F-016の証拠内にある「retry with `--force`」  
  Findingの修正手順ではなく引用元の運用説明だが、破壊的な強制終了を促す文として誤読され得る。

一方で、各Findingの「Doctor did not conclude」と「Human decision needed」は、この誘導を抑えるための適切な留保になっています。

### 評価語

- レポート自身が対象を「不要」「無駄」「bloat」「waste」「cleanup candidate」と評価した箇所はない。
- むしろContractで、そのように表現しないよう明示している。
- `Unused is not reported as a finding` として、未使用だけを理由に否定的評価しない姿勢も明記されている。
- `MUST have before fixing` はF-015の証拠として引用されたスキル本文であり、Doctor自身の評価ではない。

## 5. 採点

**2 / 5**

参照箇所、探索範囲、confidence、未確認事項、人間の判断が必要な点は整理されており、問題候補を発見する診断資料としては有用です。

しかし、妥当な修正判断に必要な以下が欠けています。

- driftの具体的な差分
- 正本と同期方針
- plugin無効化の理由
- pluginが実際に対象スキルを提供する証拠
- 次回セッションでの実測
- runtimeごとの意図
- 変更の副作用と検証・復旧方法

したがって、このレポートだけで確定できるのは、F-016を偽陽性候補として変更対象から外す判断までです。それ以外は、人間への確認と追加証拠なしに修正案を確定できません。
